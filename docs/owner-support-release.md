# Propietario: soporte, usuarios e invitaciones

- Administración y tickets: «Ver como usuario» crea una sesión Supabase real del alumno, registrada y limitada a 20 minutos. El token de retorno del propietario queda cifrado en una cookie HttpOnly. El banner permite volver; el retorno revoca solo la sesión temporal, sin cerrar otras sesiones del alumno.
- La revisión utiliza permisos reales del alumno. Proxy bloquea cambios, compras y callbacks de autenticación; políticas restrictivas de Postgres impiden escrituras de la sesión temporal y lecturas al vencer. No se cambia el progreso al revisar.
- «Eliminar usuario» exige propietario y confirmación por correo. La transacción revoca sesiones, bloquea Auth, desactiva membresías, anonimiza el perfil y archiva la cuenta. La eliminación lógica de Auth conserva referencias históricas. Se bloquean cuentas owner, propiedad activa de compañías y suscripciones pendientes de cancelación. Los datos históricos permanecen; no es un borrado físico de toda evidencia o facturación.
- Alta de propietario: casilla para enviar invitación, activada inicialmente. Sin marcarla, conserva el enlace de activación de un uso. «Enviar enlace de acceso» permite enviar correo a cuentas ya creadas. Los mensajes distinguen aceptación del proveedor de un envío rechazado. No se verificó recepción en un buzón real; SMTP y políticas de destinatarios pertenecen a la configuración del proveedor.
- Mentoría: Isaac imparte las sesiones, configura su perfil y publica disponibilidad. Se elimina la postulación de alumnos y se impide por API y SQL. Se conserva el proceso existente de solicitud y confirmación de pago externo: el alumno paga la sesión; no existe pago del propietario a terceros ni un nuevo cargo automático.
- GRC (Gobierno, Riesgo y Cumplimiento): temario previsto añadido a Coming soon. Cursos completos aún pendientes, sin fecha publicada.
- Textos nuevos en español, inglés, portugués y francés. Precios, límites y Tutor IA mantienen la configuración actual.

Validación: pruebas de decisiones de API y criptografía; fixture Postgres de permisos, bloqueo de escrituras/expiración, borrado y sesiones; prueba transaccional con rollback en producción; revisión TypeScript, cobertura de traducciones y compilación. El flujo completo con una sesión real de propietario y recepción de correo no está acreditado por estas pruebas.
